# Agent Guide

Instructions for AI coding agents (Claude Code, Codex, Cursor, OpenCode, …) working in this repo.

## Stack

Astro 7 (static output) · Svelte 5 islands · Tailwind CSS 4 · shadcn-svelte on Bits UI · Biome (lint + format) · Cloudflare Workers static assets · Node ≥26.13, pnpm 12.18 (`packageManager`).

## Commands

| Task                    | Command                                                         |
| ----------------------- | --------------------------------------------------------------- |
| Dev server (background) | `pnpm dev`, then `pnpm astro dev status/logs/stop`              |
| Lint + format check     | `pnpm check` (fix: `pnpm check:fix`)                            |
| Type check              | `pnpm typecheck` (`astro check` + `svelte-check`)               |
| Unit tests              | `pnpm test`                                                     |
| SEO gate on built HTML  | `pnpm check:seo` (also runs inside `pnpm build`)                |
| E2E + a11y              | `pnpm build && pnpm test:e2e`                                   |
| Full validation         | `pnpm validate` (check → typecheck → test → build → seo → e2e)  |
| Deploy                  | `pnpm deploy` (build + wrangler deploy; CI does this on `main`) |

Run `pnpm validate` — or at minimum `pnpm check`, `pnpm typecheck`, and `pnpm check:seo` after a build — before considering work done, and report honestly what ran and what passed. `pnpm test:e2e` serves `dist/` via `astro preview`; it needs a fresh build after any markup or script change. `pnpm check:seo` reads the existing `dist/`, so build first.

## Where things live

- `src/lib/site.ts` — single source of truth for identity, description, socials, locale, Twitter card policy, the noindex registry, metadata-length exceptions, and page copy. Pages render from it; never hardcode user-facing copy in components. Adding a page means a key under `pages`, a route under `src/pages/`, an explicit `<Layout>` title/description, an OG spec, and an entry in `tests/e2e/site.ts`.
- `src/pages/` — routes. Keep them thin: source config, render components, no business logic.
- `src/components/layouts/` — `Layout.astro` (head, theme bootstrap, page chrome) plus header, footer, container, and `mode-toggle.svelte`.
- `src/components/sections/` — composed page sections driven by `site.ts` data. Astro components that render server-side.
- `src/components/widgets/` — Svelte 5 islands with real interactivity. `music-player.svelte` owns wheel-to-volume: it attaches a **non-passive** `wheel` listener with `on()` from `svelte/events` to the player element only, and cancels the page scroll with `preventDefault()` for every gesture it handles. Order is load-bearing: modified keys, horizontal deltas, zero deltas, and a non-cancelable event all return **before** `preventDefault()` and before any state write, so refused gestures still scroll the page and the volume never changes while the page moves under it. `event.cancelable === false` is a hard stop — some browsers emit wheel sequences whose later events cannot be cancelled, and `preventDefault()` on those is a no-op. The wheel also floors at `MIN_WHEEL_VOLUME` (0.01) rather than 0: a muted player leaves the browser nothing to scroll, so the next event may arrive non-cancelable and the gesture could never recover. Do not make the listener passive, move it to `window`/`document`, or replace it with `stopPropagation()`.
- `src/lib/article-image-sizes.ts` — Sätteri HAST plugin that sets `sizes` on content images to the article column width (720px), overriding Astro's intrinsic-width default. Without it a 1920px screenshot claims `sizes="1920px"` in a 720px column and every visitor downloads the largest variant.
- `src/lib/remote-images.ts` — integration that restores remote image collection for `.mdx`. Astro's MDX path builds its collect plugin with no allowlist, so `![]()` pointing at a remote URL inside an `.mdx` file would silently ship an unoptimized `<img>`; this re-registers Astro's own collector with `config.image`. Delete it once upstream passes the config through.
- `src/components/ui/` — shadcn-svelte primitives on Bits UI. Keep them recognizable; extend via props/variants instead of restyling ad hoc.
- `src/components/seo/` — `head.astro` (the only metadata renderer: title, description, robots, canonical, RSS, Open Graph, Twitter) and `json-ld.astro` (one hashed inline `@graph` per page).
- `src/lib/seo.ts` — the metadata contract and builder. `buildPageSeo()` composes the document title, absolute canonical URL, route-derived social image, locale, Twitter card, and optional article/breadcrumb/listing data. `normalizeRoute()` and `absoluteUrl()` are the only canonical-URL helpers.
- `src/lib/seo/jsonld.ts` — `buildStructuredData()` turns the same `PageSeo` object into a `Person` + `WebSite` + page node (`WebPage`, `CollectionPage`, `BlogPosting`), plus `ImageObject`, `ItemList`, and `BreadcrumbList` when the page has that data. `serializeJsonLd()` escapes `<`, U+2028, and U+2029 before injection.
- `src/lib/seo/verify.ts` — the build gate. It recursively parses every `dist/**/*.html` with parse5 and checks metadata, canonical URLs, structured data, asset existence, OG image dimensions/uniqueness/orphans, sitemap membership, robots.txt, and the noindex registry. `src/lib/seo/quality.ts` holds the non-blocking title/description length diagnostics. `src/lib/seo/integration.ts` runs the gate at `astro:build:done`; `scripts/check-seo.mjs` exposes the same function as `pnpm check:seo`.
- `src/lib/og/` — the social-image system: `specs.ts` (derives one `OgSpec` per route from `site.pages`, `site.writing`, and the `blog` collection; there is no per-static-route list), `paths.ts` (route → `/og/….png`), `render.ts` (Satori templates + sharp rasterization). `src/pages/og/[...path].png.ts` emits the PNGs.
- `src/lib/` — shared constants and pure helpers: `site.ts` (config), `blog.ts` (post paths, sorting, draft filter, dates), `heading-permalinks.ts` (Sätteri HAST plugin for heading anchors), `theme.ts` (light/dark system), `utils.ts` (`cn` and shadcn-svelte prop helper types).
- `src/pages/robots.txt.ts` — robots.txt generated from `site.ts`; allows crawling and points at `sitemap-index.xml`. `src/pages/site.webmanifest.ts` — the web manifest generated from `site.ts` and `theme.ts`.
- `src/content.config.ts` + `src/content/blog/` — the `blog` collection: one schema for `.md` and `.mdx`, file path = slug. Authoring guide: `docs/writing.md`; templates in `docs/templates/`. The committed posts are demonstration content, safe to edit or delete.
- `src/components/blog/post-list.astro` — the editorial list shared by the homepage Writing section and `/blog/`.
- `src/components/sections/writing.astro` — homepage section: newest four posts; the heading is the only link to `/blog/` (no duplicate "view all").
- `src/styles/global.css` — Tailwind, shadcn semantic tokens, theme variables, and the typography plugin registration. `src/styles/prose.css` — article typography (token mapping for `prose` plus the Shiki dark-palette overrides), imported only by the article route. Syntax themes are the high-contrast GitHub pair set in `astro.config.mjs`; the stock pair fails AA on comments, so don't switch back.
- `tests/unit/` — vitest tests of shared constants, blog helpers, the blog schema, SEO composition, and structured data. `tests/e2e/` — Playwright smoke, accessibility, CSP, theme, SEO/JSON-LD, social images, widget, music-player, homepage writing, blog, MDX island, and link checks.

## Astro vs Svelte

- Astro owns static rendering: pages, layouts, content sections, SEO markup, header/footer, and future blog/article rendering.
- Svelte owns client interaction: theme toggling, the clock, the LED matrix, the music player, and future stateful tools.
- Do not hydrate static markup. A Svelte component rendered without a `client:*` directive runs on the server and ships no component JavaScript — use that for presentational shadcn-svelte primitives in `.astro` files.
- Choose the cheapest hydration directive that works: `client:load` for controls needed immediately (theme toggle), `client:idle` for non-critical widgets, `client:visible` for below-fold or heavy widgets.
- Pass props directly from Astro. The default slot maps to the Svelte `children` snippet. Astro cannot pass Svelte snippets, so keep component APIs prop-based.

## Svelte 5 conventions

- Use runes only. `$state` for reactive state, `$derived` for computed values, `$effect` for external side effects and synchronization, `$props` for props, and `$bindable` for two-way component props.
- Do not use `$effect` to calculate values that should be `$derived`.
- Props: declare an `interface Props`, destructure with `$props()`, and expose a `class` prop when the component is styled by its parent. Merge classes with `cn`.
- Events: use event attributes (`onclick`, `onplay`, `onpause`), not `createEventDispatcher` or `on:click`.
- Callbacks: pass functions as props (`onValueChange`, `onToggle`). Do not invent event buses or stores for parent/child communication.
- Lifecycle: return a cleanup function from `$effect`. Use `onMount` only when a value must be read after mount; otherwise an effect is enough.
- State stays local to the island. Astro islands do not share client state; use `site.ts` for build-time data and avoid global stores unless two islands genuinely need shared runtime state.
- Refs: use `bind:this` for DOM elements. shadcn-svelte components expose a bindable `ref` prop — use `bind:ref`.
- Keep components small and cohesive. Extract a child component only when it removes real duplication or clarifies a boundary.
- Accessibility: label icon-only controls with `aria-label`, mark decorative icons `aria-hidden="true"`, use `aria-pressed` for toggles, keep visible `focus-visible:ring-3` states, and respect `prefers-reduced-motion` with `motion-safe:` or explicit media queries.
- Styling: Tailwind utilities with semantic tokens (`bg-background`, `text-muted-foreground`) — never raw hex or oklch values in markup. Token definitions change only in `global.css`.
- Icons: import named icons from `@lucide/svelte`. Pass `class` for sizing and `aria-hidden="true"` when decorative.
- Imports: always the `@/` alias; Biome rejects relative imports.
- shadcn-svelte: add components with `pnpm dlx shadcn-svelte@latest add <name>`, not by copying examples. Components live under `src/components/ui/<name>/` with an `index.ts`. Keep the project's neutral tokens and zero-radius geometry; do not apply a default shadcn theme. Remove unused subcomponents and variants.
- Testing: update or add a case in `tests/e2e/widgets.spec.ts` when an interaction changes. Wait for hydration with `astro-island[component-url*="<name>"]:not([ssr])` before clicking an island control.

## Rules

- **Theme.** Dark is the default. All theme constants live in `src/lib/theme.ts`; the pre-paint bootstrap is inlined by `Layout.astro` and the toggle is `mode-toggle.svelte` hydrated with `client:load`. The bootstrap's fallback rule is inline by necessity (it runs before modules) and is covered by `tests/e2e/theme.spec.ts`, including invalid, missing, and blocked storage. Don't introduce another storage key, color map, or bootstrap.
- **CSP is on.** Never add `'unsafe-inline'` to `script-src`, never write raw inline HTML event handler attributes (`onclick="..."`), and never use inline scripts. Svelte 5 event attributes such as `onclick={handler}` are valid and encouraged — Svelte compiles them to `addEventListener`, so they ship no inline script. Astro hashes bundled scripts automatically; an `is:inline` script must register its hash via `Astro.csp.insertScriptHash` (see `Layout.astro` for the pattern). Style attributes are allowed (`style-src-attr 'unsafe-inline'`) because Bits UI positions elements with them; `<style>` elements stay hash-locked. `frame-ancestors` cannot be enforced from a meta tag, so clickjacking protection is `X-Frame-Options: DENY` in `public/_headers` (applied by Cloudflare). `pnpm test:e2e` fails on CSP violations.
- **Content.** Copy comes from `site.ts` (writing copy under `site.writing`). Never invent content — no posts, projects, tools, metrics, or testimonials that don't exist.
- **Blog.** Publishing is a `.md` or `.mdx` file in `src/content/blog/`; `docs/writing.md` is the authoring contract. The collection (`src/content.config.ts`) uses `glob()` over both extensions with one schema: `title`, `description`, `pubDate`, optional `updatedDate`, `draft` (default `false`). The file path is the slug — never add a `slug` field. Drafts are excluded by `publishedPosts()` in `src/lib/blog.ts`, which every surface (homepage, archive, `[...slug]` routes, RSS, sitemap) goes through; don't filter inline. The homepage shows `recentPosts(posts, 4)` and renders no section when that is empty. The header deliberately has no Blog/Writing link — the homepage section and `/blog/` are the entry points. `@astrojs/mdx` and `@astrojs/sitemap` are registered in `astro.config.mjs`; `/rss.xml` is `src/pages/rss.xml.ts`.
- **Markdown vs MDX.** Default to `.md`; use `.mdx` only for a post that composes a component. Astro and Svelte components import with `@/` and render statically by default; add the cheapest `client:*` directive only where interaction is real. Both formats share `src/pages/blog/[...slug].astro` and the `prose` utility from `@tailwindcss/typography` (tokens mapped in `src/styles/prose.css`) — style articles there, not in per-post markup.
- **Markdown processor is Sätteri.** Astro 7 processes Markdown and MDX with Sätteri, not Unified. Extend it through `markdown.processor: satteri({ hastPlugins })` in `astro.config.mjs`; `satteriHeadingIdsPlugin()` must run before any plugin that reads heading IDs (it is what assigns them), and `.md` and `.mdx` share that processor, so a plugin registered there covers both. Never add `remarkPlugins`/`rehypePlugins` or Unified-only packages (`rehype-slug`, `rehype-autolink-headings`) — they are ignored by this processor. Heading permalinks are `headingPermalinksPlugin` in `src/lib/heading-permalinks.ts`; the `#` glyph is CSS (`.heading-anchor::after` in `prose.css`) so heading metadata text stays clean.
- **SEO is centralized and mandatory.** `Layout.astro` requires explicit `title` and `description` props — there are no homepage defaults, so a new route cannot silently inherit another page's copy. Every title, description, canonical URL, Open Graph tag, Twitter tag, favicon link, and JSON-LD graph is generated from that one interface by `head.astro` and `src/lib/seo.ts`. Never write metadata tags in a page; pass page facts to `Layout.astro` instead.
  - **Canonical URLs.** `buildPageSeo()` produces absolute HTTPS URLs on `site.url`, strips query strings and fragments, and forces the trailing slash that `trailingSlash: "always"` and the `directory` build format use. `pnpm check:seo` fails if a canonical is relative, off-origin, query-bearing, duplicated, or does not match the page's own route.
  - **Page-specific metadata.** Homepage: `site.pages.home.seoTitle` / `site.description`. Archive: `site.writing.seoTitle` / `site.writing.description` plus breadcrumbs and the real post list. Articles: the collection entry's `title`, `description`, `pubDate`, optional `updatedDate`. `seoTitle` is the document-title base; the ` — mihidana` suffix is appended once by `buildPageSeo()`, so never include it yourself. The visible `<h1>` stays separate (`site.pages.home.title`, `site.writing.title`, the post title). Never reuse the homepage's title or description for another page; the validator fails duplicate titles and descriptions across the build.
  - **Metadata quality.** `src/lib/seo/quality.ts` warns — without failing the build — when a title falls below 30 or above 70 characters, or a description below 80 or above 200. The editorial target is 50–60 characters for titles and 110–160 for descriptions; a page near the target is fine. Warnings name the route, the current length, and the target. For an intentional exception, add `{ route, field, reason }` to `site.seo.metadataExceptions`; the reason is required, the route must be an indexable built page, and only that one length warning is suppressed. Correctness failures are never exempt.
  - **Open Graph and Twitter.** `head.astro` emits `og:title`, `og:description`, `og:type`, `og:url`, `og:site_name`, `og:locale`, and the full image block, plus `twitter:card/title/description/image/image:alt`. OG and Twitter values come from the same object, so they cannot drift. `twitter:site` and `twitter:creator` are emitted only when a verified handle exists in `site.seo.twitter`; never invent one.
  - **Noindex.** Pass `noindex` to `Layout.astro` **and** add the route to `site.seo.noindexRoutes`. The page then ships `robots: noindex, nofollow`, omits social images and uses `twitter:card=summary`, and `@astrojs/sitemap` filters it out. No card is generated for the route: `staticOgSpecs()` filters `site.seo.noindexRoutes`, so a noindex page cannot leave an orphaned image, and the gate reports an image no page references. The build gate fails if a noindex page is unregistered, if a registered page is indexable, if a noindex route appears in the sitemap, or if an indexable page is missing from it. This is the only supported exemption; there are no silently skipped pages.
  - **Structured data.** `buildStructuredData()` emits one inline `@graph` per page: `Person`, `WebSite`, a `WebPage`/`CollectionPage` page entity, `BlogPosting` for articles, `ItemList` for listings, `BreadcrumbList` for every sub-page, and an `ImageObject` when the page has a card. It uses only real data from the page and `site.ts`; no ratings, reviews, awards, organizations, authors, or dates are invented. `json-ld.astro` registers the exact payload's CSP hash — any new inline script needs the same treatment.
  - **Adding a public page.** Add one entry under `site.pages` with `route`, `title`, `description`, and (when the visible heading is not a good search title) `seoTitle`, then render the route through `Layout.astro` with the same `title`/`description` (plus `breadcrumbs` for sub-pages, `type="article"` and dates for articles, `items` for listings). Add the route to `tests/e2e/site.ts` and run `pnpm build && pnpm check:seo`. The social card is derived from that entry automatically — there is no `OgSpec` to add. A route that bypasses `Layout.astro` still fails the gate, and so does a route whose rendered title/description disagrees with `site.pages`, because the gate reads every emitted HTML file rather than a maintained list.
- **Article metadata.** Articles pass `type="article"`, `publishedTime`, `modifiedTime`, and a `breadcrumbs` trail to `Layout.astro`. `head.astro` emits the matching `article:published_time`/`article:modified_time` tags, and the centrally generated graph adds `BlogPosting` with the real `headline`, description, canonical URL, dates, author/publisher `@id` references, and the page's generated image. No author name, organization, or image is invented beyond the configured site identity.
- **Images.** Use standard Markdown `![]()` for ordinary images; Astro's image service optimizes them at build time and MDX must not be required for that. Local images live under `src/` — `src/assets/blog/` for images shared across posts, or a folder beside the post (`src/content/blog/<post>/diagram.png`) referenced relatively. Remote images are any public **direct HTTPS image URL from any host** — `image.remotePatterns` is `[{ protocol: "https" }]` on purpose, so never add a per-provider `hostname` entry. Use the image address, not the containing webpage URL (`i.redd.it` yes, `reddit.com/r/…/comments/…` no). Never use a raw `<img>` for an image expected to be optimized, and never put optimizable blog images in `public/` — it is copied verbatim and unoptimized. In MDX, use `astro:assets` `<Image />` for explicit size/format control and `<Picture />` for multiple formats. The build fetches remote images, so a blocked or deleted host fails the build rather than falling back silently — that is intended, because CSP is `img-src 'self' data:`.
- **Sitemap, robots, and favicons.** `@astrojs/sitemap` emits only the built pages, on the `site.url` origin, filtered by `site.seo.noindexRoutes`; `robots.txt` is generated from the same config and always points at `sitemap-index.xml`. `Layout.astro` is the only place favicon/manifest links are declared: SVG first (`/favicon.svg`, light/dark aware), then the existing ICO/PNG fallbacks, apple-touch-icon, and the generated manifest. Do not add per-page icon links.
- **Open Graph images are automatic and mandatory.** Every indexable page ships `og:image` and `twitter:image` pointing at a card generated during `astro build`, plus width/height/type/alt and `twitter:card=summary_large_image`. Nothing ships to the browser: Satori and sharp run only at build time and the endpoint is a static file.
  - **How a page gets one.** `head.astro` derives the image URL from the page's own pathname via `ogImagePath()` (`src/lib/og/paths.ts`): `/` → `/og/home.png`, `/blog/` → `/og/blog.png`, `/blog/<slug>/` → `/og/blog/<slug>.png`, `/about/` → `/og/about.png`. Nested routes stay nested.
  - **No override.** There is no `image` prop. Every page uses its generated card; a hand-picked asset could not be verified against the build, so it would either ship unvalidated or fail the gate. If that ever changes, the override must also emit its own width/height/type and be taught to the verifier.
  - **Slugs and encoding.** Slugs may be any string the file system accepts, including spaces and Unicode. A route arrives percent-encoded from `Astro.url.pathname` and raw from `CollectionEntry.id`; each segment is decoded individually (never the whole path, so `%2F` cannot become a directory) and both forms map to one file. Segments that are already lowercase `[a-z0-9-]` keep their name; everything else is ASCII-folded and suffixed with a 64-bit base36 hash of the decoded segment. The hash is a disambiguator, **not** a proof of collision-freedom.
  - **Uniqueness is enforced, not assumed.** `assertUniqueOgPaths()` runs inside `getStaticPaths()` before any PNG is rendered and throws, naming both routes, if a route is declared twice or two routes resolve to the same file.
  - **The image's content is derived, never listed.** `staticOgSpecs()` maps every `site.pages` entry through `pageOgSpec()`, using that page's `route`, `seoTitle`/`title`, and `description`; `site.writing` supplies the archive card. Articles read their collection entry (`title`, `description`, `pubDate`) through `publishedPosts()`. `pageOgSpec()` selects the kind — `home` keeps the identity design, everything else gets the generic `page` template — and articles keep the `article` template. There is no per-static-route list to update.
  - **Adding a public page.** Add the metadata under `site.pages` (already required for the HTML) and render the route through `Layout.astro`. The card is generated automatically from that entry; the gate fails if the built page's title/description disagrees with it, or if a page is built without an entry.
  - **The gate.** `seoCheck()` (`src/lib/seo/integration.ts`) runs after the build, reads every `dist/**/*.html`, and fails `pnpm build` if a page lacks any social meta tag, points at an image that was not emitted, points at something that is not a 1200×630 PNG, shares an image with another page, or if a generated image is referenced by nobody. It also requires each page's `og:image` to be exactly the route-derived path; requires every `site.pages`/`site.writing` entry to be a built page whose rendered title and description match it; and checks that the `WebSite` description matches `site.ts`, that `Person`/`WebSite`/page/article references resolve to one another, that `BlogPosting` dates match the emitted article tags, and that listing and breadcrumb entries point at real pages. It names the offending route. Metadata length diagnostics are logged as warnings and do not fail the build. `404.html` is the one technical file exempt from page metadata; it must ship `noindex` and must not emit a canonical link, structured data, or social images.
  - **Fonts.** Satori draws a variable font at its default instance only, ignoring `fontWeight`, so `astro.config.mjs` declares a second Satoshi family (`--font-og-satoshi`, weights 400/700, normal) for the cards; the site keeps the variable face. Fonts come from `fontData`/`experimental_getFontFileURL` — no remote fetch at render time, no font files committed. Caveat (variable, single weight) is fine for the wordmark.
  - **Caching.** `/og/*.png` URLs are page-stable, not content-hashed, so they must not be served `immutable`; `public/_headers` sets `max-age=0, must-revalidate` for `/og/*`. Static builds drop endpoint response headers, so the policy belongs there.
- **Accessibility.** `Layout.astro` owns the single `<main id="main">` and skip link; one `<h1>` per page; visible `focus-visible:ring-3` states on interactive elements; `aria-label` on icon-only controls. E2E enforces WCAG 2 A/AA — serious or critical violations fail the build.
- **Dependencies.** Minimal. Every new dependency needs a justification in the change description; prefer native Astro capabilities and official integrations. `bits-ui`, `tailwind-variants`, and `@internationalized/date` are shadcn-svelte component dependencies; keep them in sync with the generated components.
- **Secrets.** `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` live in CI secrets; local env vars in `.env` (names in `.env.example`). Never commit secrets.
- **Docs.** Keep `README.md` and `PRODUCT.md` describing actual behavior, updated in the same change as the code.
- **Validation.** CI runs check, typecheck, unit tests, build, `pnpm check:seo`, and E2E, and deploy only happens after all of them pass. Don't weaken the workflow to make a change land.

## AI tooling

- **OMP:** `.omp/mcp.json` keeps the `astro-docs` HTTP server and adds the official Svelte stdio server (`npx -y @sveltejs/mcp`). Preserve both.
- **OpenCode:** `opencode.jsonc` loads the official `@sveltejs/opencode` plugin. `.opencode/svelte.json` enables its MCP server, skills, instructions, and `svelte-file-editor` subagent. Do not register a second Svelte MCP server in `opencode.jsonc`.
- **Skills:** project skills install to `.agents/skills/` (gitignored); `skills-lock.json` is tracked. The active shadcn skill is `huntabyte/shadcn-svelte` — install with `pnpm dlx skills add huntabyte/shadcn-svelte`.
- **Docs:** use the `astro-docs` MCP server (`search_astro_docs`) for Astro APIs and the Svelte MCP tools for Svelte documentation, examples, and code validation.

## Conventions

- Biome is the only formatter/linter and formats `.svelte` files too (2-space indent, 100 columns, LF). Don't add ESLint, Prettier, or a Svelte formatter plugin.
- Commit history follows Conventional Commits (`feat(scope):`, `docs(site):`, …).
- Prefer focused edits to existing files over rewrites; don't reformat untouched code.
- Keep comments only when they explain a non-obvious architectural decision, a browser compatibility workaround, a security or CSP constraint, an accessibility requirement, a difficult edge case, or a licensing obligation. Remove comments that narrate obvious code or repeat names.
